# English Game Library — техническая спецификация первой версии

**Версия документа:** 1.0  
**Язык интерфейса ученика:** простой английский  
**Язык Teacher Editor и сообщений проверки:** русский  
**Целевая аудитория:** дети 10–11 лет, изучающие английский язык  
**Учебная тема первой версии:** Past Simple  
**Статус:** инструкция для будущей разработки; этот документ не является программным кодом

---

## 1. Общая идея проекта

### 1.1. Назначение

**English Game Library** — локальный образовательный сайт с тремя играми по английскому языку. В первой версии ребёнок тренирует Past Simple, получает очки, звёзды и достижения, а учитель создаёт собственные темы без программирования.

Первая версия работает без сервера, онлайн-регистрации и передачи данных в интернет. Профили учеников и их прогресс хранятся в браузере на конкретном устройстве.

### 1.2. Планируемые технологии

- React — интерфейс из повторно используемых компонентов.
- TypeScript — описание структуры данных и защита от части ошибок.
- Vite — сборка и локальный запуск проекта.
- React Router — переходы между страницами.
- CSS Modules или обычный CSS — оформление. Для первой версии рекомендуется CSS Modules для игровых компонентов и один общий файл с цветами, шрифтами и размерами.
- `localStorage` — небольшие настройки и прогресс.
- IndexedDB — пользовательские темы и загруженные файлы.
- Web Audio API или локальные аудиофайлы — музыка и эффекты.
- Browser Text-to-Speech — чтение готовой истории в Adventure Storyboard.

### 1.3. Визуальное направление

Стиль объединяет приключения в Древнем Египте и современный образовательный интерфейс. Основные цвета:

- тёмно-бирюзовый — основные панели и кнопки;
- золотой — рамки, награды и активные элементы;
- песочный — карточки и области с текстом;
- тёплый коричневый — камень, дерево, тени;
- оранжевый — предупреждения и ошибки;
- светлый кремовый — основной текст на тёмном фоне.

Персонажи полуреалистичные, доброжелательные и уверенные. Нельзя использовать чрезмерно упрощённые «малышовые» лица, кислотные цвета, пугающих мумий или мрачные сцены.

### 1.4. Как использовать визуальный референс

В задании указан `public/images/main-interface.png`. В текущем проекте файл по этому пути отсутствует; визуально соответствующий файл найден в корне под именем `main- interface.png.png`. Он используется только как ориентир композиции. Перед разработкой желательно привести имя ресурса к согласованному пути, не меняя саму идею интерфейса.

Референс нельзя растягивать на страницу как одну большую фоновую картинку. Интерфейс нужно собрать из независимых слоёв:

1. `EgyptBackground` — декоративный фон: градиент закатного неба, отдельные изображения пирамид, Нила, храмов, пальм и ближних каменных стен. На маленьких экранах второстепенные слои скрываются.
2. `TopHeader` — верхняя панель с логотипом, профилем и служебными кнопками.
3. `BrandSign` — отдельная бирюзово-золотая вывеска **English Game Library** со слоганом **PLAY • LEARN • ADVENTURE**. Текст остаётся настоящим текстом, а не частью картинки.
4. `ExplorerHero` — отдельное изображение одного или двух исследователей. Оно декоративно поддерживает тему, но не перекрывает управление.
5. `SectionBanner` — вывеска **CHOOSE YOUR GAME**.
6. `GameCard` — три самостоятельные карточки из светлого «камня» с номером, обложкой, названием, описанием, статистикой и кнопками.
7. `PrimaryButton` и `SecondaryButton` — крупные бирюзовые кнопки с золотой рамкой; состояние нажатия, фокуса и недоступности создаётся стилями.
8. `EgyptianFrame`, `ScarabBadge`, `HieroglyphDivider` — небольшие декоративные рамки, скарабеи и орнаменты. Они не должны мешать чтению.
9. `ProfileSummary` — имя, аватар, уровень и звёзды как отдельный компактный блок.
10. `Modal` — универсальный компонент поверх страницы для How to Play, паузы и подтверждений.

На широком экране допустима композиция, похожая на референс: логотип и персонажи в верхней части, три карточки в один ряд ниже. При этом служебные кнопки должны быть читаемыми и не сливаться с декорациями. Карточки не обязаны повторять перспективный наклон из изображения: прямые карточки проще читать и адаптировать.

### 1.5. Общие правила интерфейса

- Основные действия подписаны словами, даже если рядом есть значок.
- Игровой текст на английском короткий и понятный.
- Системные ошибки Teacher Editor показываются по-русски.
- В одной области должен быть один очевидный главный следующий шаг.
- Декор не должен выглядеть как кнопка.
- Результат любого нажатия должен быть заметен: изменение состояния, короткая анимация или сообщение.

## 2. Главная страница

### 2.1. Назначение и порядок блоков

Главная страница по маршруту `/` помогает выбрать профиль и игру. Сверху вниз располагаются:

1. `TopHeader`.
2. Брендовая зона с логотипом, слоганом и персонажами.
3. Заголовок **CHOOSE YOUR GAME**.
4. Сетка из трёх `GameCard`.
5. Небольшая нижняя строка со ссылкой на Teacher Editor и информацией о локальном хранении данных.

### 2.2. Верхняя часть

В `TopHeader` обязательно находятся:

- логотип **English Game Library**;
- слоган **PLAY • LEARN • ADVENTURE**;
- кнопка **Achievements**;
- кнопка **My Progress**;
- кнопка **Settings**;
- имя выбранного ученика;
- текущий уровень, например `Level 2`;
- количество звёзд, например `⭐ 14`;
- кнопка **Sound On / Sound Off** с иконкой и текстовой подсказкой.

На телефоне служебные кнопки допускается собрать в меню, но имя, уровень, звёзды и управление звуком должны оставаться доступны без длинного поиска.

### 2.3. Карточки игр

На странице всегда показаны три крупные карточки:

1. **Mummy Memory** — *Match the irregular verbs.*
2. **Verb Treasure Quest** — *Choose the correct verb form.*
3. **Adventure Storyboard** — *Make a story from pictures.*

Каждая `GameCard` содержит:

- номер игры 1, 2 или 3;
- отдельный логотип или обложку;
- название;
- короткое описание;
- кнопку **PLAY NOW**;
- кнопку **HOW TO PLAY**;
- число полученных звёзд от 0 до 3;
- лучший результат ученика;
- отметку **Completed**, если выбранная тема пройдена хотя бы один раз.

Если для типа игры есть несколько опубликованных тем, **PLAY NOW** сначала открывает простой выбор темы. Если доступна только одна тема, игра открывается сразу. **HOW TO PLAY** открывает модальное окно поверх главной страницы; адрес страницы не меняется, фон затемняется, фокус клавиатуры остаётся внутри окна.

### 2.4. Состояния

- Пока профиль не выбран, вместо запуска показывается диалог выбора или создания локального ученика.
- Если у игры нет опубликованной темы, **PLAY NOW** неактивна и рядом написано: `No topics available yet.`
- Лучший результат показывается как `Best: 180 points`; до первой попытки — `Best: —`.
- Завершение обозначается текстом и значком, а не только цветом.

## 3. Игра 1 — Mummy Memory

### 3.1. Цель

Ребёнок находит пары «начальная форма — Past Simple»: `go — went`, `see — saw`, `take — took`, `find — found`, `eat — ate`, `buy — bought`.

### 3.2. Игровой экран

На экране находятся:

- название темы;
- сетка карточек;
- счёт;
- таймер;
- число ходов;
- число оставшихся пар;
- **Pause**;
- **Restart**;
- **How to Play**;
- **Sound**;
- **Home**.

Карточки имеют одинаковую египетскую рубашку. Лицевая сторона показывает одно слово и при необходимости небольшую картинку. Базовая и прошедшая формы не различаются цветом: ученик должен прочитать слово.

### 3.3. Логика одного хода

1. В начале все карточки закрыты и перемешаны.
2. Нажатие открывает первую карточку.
3. Нажатие на другую закрытую карточку открывает вторую.
4. Во время проверки сетка временно блокируется: третью карточку открыть нельзя.
5. Если слова составляют пару, обе карточки получают подпись `Match!` и остаются открытыми.
6. Если пара неверна, обе карточки остаются видимыми одну секунду, затем закрываются.
7. Один ход считается после открытия двух разных карточек.
8. Игра заканчивается, когда найдено всё.

Повторное нажатие на уже открытую карточку ничего не делает. Пауза останавливает таймер, блокирует сетку и закрывает игровое содержимое панелью `Game paused`.

### 3.4. Очки и точность

- правильная пара: `+20` очков;
- серия из трёх правильных пар подряд: дополнительный бонус `+10`; затем серия продолжается, и следующий бонус начисляется за следующие три правильные пары;
- неправильная пара: `0` очков и сброс текущей серии;
- бонус за время после завершения: `max(0, 300 − elapsedSeconds)`, но не более 300 очков.

Формула бонуса фиксируется заранее, чтобы результат был предсказуемым. Точность равна `правильные ходы / все ходы × 100%`. Результат округляется до целого процента.

### 3.5. Завершение и звуки

После последней пары таймер останавливается, результат сохраняется и открывается Victory Screen. Используются звуки:

- переворот карточки;
- правильная пара;
- неправильная пара;
- получение бонуса серии;
- завершение игры.

## 4. Игра 2 — Verb Treasure Quest

### 4.1. Цель и содержание

Ребёнок выбирает правильную форму глагола в одном предложении. Набор должен включать:

- утвердительные предложения;
- отрицательные предложения с `didn’t`;
- вопросы с `Did`;
- краткие ответы;
- правильные глаголы;
- неправильные глаголы.

Обязательное правило темы: **после `did` и `didn’t` используется начальная форма глагола**. Оно показывается в обучении и в подходящих подсказках.

Пример:

> She ___ the treasure yesterday.  
> A. find  
> B. found  
> C. finds

Правильный ответ: `found`.

### 4.2. Игровой экран

На экране находятся:

- `Question 1 of 10`;
- предложение;
- три большие кнопки ответа A, B и C;
- область подсказки;
- три сердца;
- счёт;
- маршрут и прогресс движения персонажа к сундуку;
- **Pause**, **Restart**, **How to Play**, **Sound**, **Home**.

### 4.3. Логика вопроса

1. Показывается одно предложение и три ответа.
2. При первом правильном ответе начисляется 20 очков, персонаж идёт на один шаг, затем появляется следующий вопрос.
3. После первой ошибки ответ помечается знаком ошибки, теряется одно сердце и показывается короткая грамматическая подсказка. Два оставшихся варианта доступны.
4. При правильном ответе со второй попытки начисляется 10 очков.
5. После второй ошибки теряется ещё одно сердце, показываются правильный ответ и объяснение. За вопрос начисляется 0 очков; затем доступна кнопка **NEXT**.
6. После всех заданий персонаж достигает цели и сундук открывается.

Сердца здесь показывают допустимые ошибки в текущей серии, но их отсутствие не завершает игру досрочно: после нуля сердец правильный ответ раскрывается, а на следующем вопросе снова показываются три сердца. Это делает механику обучающей, а не наказующей.

### 4.4. Очки, точность и время

- правильный ответ с первой попытки: `+20`;
- правильный ответ со второй попытки: `+10`;
- ответ, раскрытый после двух ошибок: `0`;
- бонус за время: `max(0, 300 − elapsedSeconds)`, максимум 300.

Точность для звёзд считается как число вопросов, отвеченных верно до раскрытия ответа, делённое на общее число вопросов. Первая и вторая успешная попытка считаются правильным вопросом.

### 4.5. Звуки

- нажатие кнопки;
- правильный ответ;
- неправильный ответ;
- движение по маршруту;
- потеря сердца;
- открытие сундука;
- победа.

## 5. Игра 3 — Adventure Storyboard

### 5.1. Обложка и цель

На обложке изображена оригинальная египетская царевна, вдохновлённая образом Нефертити, но не являющаяся копией конкретного музейного портрета или изображения. Она держит веером несколько карточек; видны только одинаковые рубашки. На обложке нельзя показывать десять маленьких сюжетов подряд.

Внутри одной истории обязательно от 10 до 20 сюжетных карточек. Встроенная история первой версии содержит ровно 10 карточек.

### 5.2. Общий экран

Всегда видны:

- название истории;
- текущий этап: `Stage 1 of 3`, `Stage 2 of 3` или `Stage 3 of 3`;
- общий прогресс;
- счёт;
- оставшееся количество подсказок;
- предварительно заработанные звёзды;
- **Restart**, **How to Play**, **Sound**, **Home**.

### 5.3. Этап 1 — Story Order

- Сюжетные картинки перемешиваются в отдельной области.
- На линии времени находятся пронумерованные позиции. Для встроенной истории — от 1 до 10; для пользовательской — от 1 до фактического количества карточек.
- Карточку можно перетащить мышью, пальцем или поставить клавиатурой через действие **Move to position…**.
- **CHECK ORDER** проверяет текущую последовательность.
- Правильная карточка получает бирюзово-золотую рамку, значок галочки и текст `Correct position`.
- Ошибочная получает оранжевую рамку, значок перестановки и текст `Try another position`.
- Полная последовательность не раскрывается автоматически.
- **HINT** открывает одну ещё не открытую правильную позицию и уменьшает запас подсказок.

В начале доступно 3 подсказки. За каждую правильно размещённую карточку при проверке начисляется 10 очков только один раз. Каждая использованная подсказка уменьшает итоговый счёт на 5, но счёт не может стать отрицательным.

### 5.4. Этап 2 — Make Sentences

После правильной расстановки ученик проходит картинки по порядку и создаёт предложение в Past Simple.

**Support Mode**:

- показываются картинка и три предложения;
- за правильный выбор с первой попытки — 10 очков;
- после ошибки показывается подсказка, за правильный выбор со второй попытки — 5 очков;
- после второй ошибки раскрывается ответ, 0 очков.

**Challenge Mode**:

- ребёнок печатает предложение самостоятельно;
- перед сравнением обе строки переводятся в нижний регистр;
- несколько пробелов заменяются одним, пробелы по краям удаляются;
- одна точка в конце не учитывается;
- апострофы в `didn't` должны приниматься как прямые `'` и типографские `’`;
- другие слова, порядок слов и грамматические формы должны совпадать с одним из допустимых ответов;
- за правильный ответ с первой попытки — 15 очков, со второй — 8, после раскрытия — 0.

Режим выбирается до начала этапа 2 и сохраняется в результате. Учитель может добавить допустимые варианты формулировки, чтобы правильная по смыслу фраза не считалась ошибкой только из-за безопасного варианта написания.

### 5.5. Этап 3 — Complete Story

Показываются все картинки по порядку, готовые предложения и единый рассказ. Предложения связываются словами:

`First,` → `Then,` → `Next,` → `After that,` → `Later,` → `Finally,`.

Если предложений больше шести, связки можно повторять осмысленно, например `Then` и `Next`, но первое предложение всегда начинается с `First`, а последнее — с `Finally`.

Кнопка **READ STORY** запускает браузерный Text-to-Speech с английским голосом. Должны быть кнопки **Pause Reading**, **Continue** и **Stop**. Если английский голос недоступен, показывается спокойное сообщение: `Reading is not available in this browser.` Текст всё равно остаётся на экране.

После просмотра полного рассказа игра считается завершённой и открывает Victory Screen.

### 5.6. Точность

Точность этапа 1 — доля карточек, оказавшихся на верных позициях при первой полной проверке. Точность этапа 2 — доля предложений, выполненных до раскрытия ответа. Итоговая точность — среднее арифметическое двух значений. Подсказки влияют на очки, но не изменяют формулу точности.

## 6. Окна How to Play

### 6.1. Общие требования к модальному окну

Каждая инструкция содержит название игры, крупную тематическую иллюстрацию, 3–5 коротких шагов, очки, награду, **START GAME** и кнопку закрытия `×` с доступным названием `Close instructions`. Окно закрывается также клавишей `Escape`. Иллюстрация является отдельным изображением с `alt`, а текст — настоящим HTML-текстом.

### 6.2. Mummy Memory — текст для ребёнка

**MUMMY MEMORY**  
*Find the matching verb cards!*

1. Turn over two cards.
2. Match the base verb with its Past Simple form.
3. A correct pair stays open.
4. Find all pairs and finish as fast as you can.

**Points:** Get 20 points for each pair. Match three pairs in a row for 10 bonus points. Finish faster for a time bonus.  
**Reward:** Earn up to 3 stars and unlock **MEMORY MASTER**.  
Buttons: **START GAME**, **CLOSE**.

### 6.3. Verb Treasure Quest — текст для ребёнка

**VERB TREASURE QUEST**  
*Choose the correct verb and reach the treasure!*

1. Read the sentence.
2. Choose A, B, or C.
3. Use the hint if your first answer is wrong.
4. Remember: use the base verb after **did** and **didn’t**.
5. Answer all questions to open the chest.

**Points:** Get 20 points on your first try or 10 on your second try. Finish faster for a time bonus.  
**Reward:** Earn up to 3 stars and unlock **VERB EXPLORER**.  
Buttons: **START GAME**, **CLOSE**.

### 6.4. Adventure Storyboard — текст для ребёнка

**ADVENTURE STORYBOARD**

## 7. Редактор тем для учителя

### 7.1. Доступ и список тем

Маршрут `/teacher` защищён четырёхзначным PIN-кодом. При первом входе учитель создаёт PIN и повторяет его. В следующих сессиях вводит PIN. PIN хранится локально в виде хеша с солью, а не открытым текстом. Это защита от случайного входа ребёнка, а не полноценная система безопасности. После пяти неверных попыток ввод блокируется на 30 секунд.

На странице списка можно:

- создать новую тему;
- открыть и изменить существующую;
- дублировать тему с новым `id`, названием `Copy of …` и статусом `Draft`;
- сохранить черновик;
- опубликовать;
- удалить после отдельного подтверждения;
- импортировать JSON;
- экспортировать JSON;
- открыть предварительный просмотр.

### 7.2. Пошаговый мастер

Сверху показываются четыре шага и текущая позиция. Переход вперёд разрешён, если обязательные поля текущего шага заполнены. **BACK** не удаляет введённые данные. **CANCEL** просит подтверждение, если есть несохранённые изменения.

#### Шаг 1 — General Information

Поля:

- название темы — обязательное, 3–80 символов;
- тип игры — `memory`, `quest` или `storyboard`; после добавления контента смена типа требует подтверждения;
- короткое описание — обязательное, до 180 символов;
- сложность — `Easy`, `Medium`, `Hard`;
- изображение обложки — JPG, PNG или WebP, до 5 МБ;
- количество звёзд за прохождение — 1–3; для стандартной системы рекомендуется 3;
- статус — `Draft` или `Published`.

#### Шаг 2 — Add Content: Mummy Memory

Для каждой пары:

- `Base verb`;
- `Past Simple form`;
- дополнительная картинка;
- дополнительное аудио;
- кнопка удаления.

Внизу — **ADD VERB PAIR**. Разрешено от 4 до 20 пар. Оба текстовых поля обязательны. Сравнение дубликатов не учитывает регистр и пробелы по краям. Нельзя повторять одинаковую пару и нельзя использовать одну и ту же форму в конфликтующих парах без явного предупреждения.

#### Шаг 2 — Add Content: Verb Treasure Quest

Для каждого вопроса:

- текст предложения с одним пропуском `___`;
- глагол в скобках;
- вариант A;
- вариант B;
- вариант C;
- правильный ответ;
- грамматическая подсказка;
- объяснение;
- дополнительная картинка;
- **ADD QUESTION**.

Разрешено от 5 до 30 вопросов. Все три варианта должны быть заполнены и различаться после нормализации. Правильный только один и обязан точно совпадать с A, B или C. Предложение должно содержать один пропуск.

#### Шаг 2 — Add Content: Adventure Storyboard

Для каждой карточки:

- загрузка картинки;
- номер события;
- название события;
- правильное предложение;
- два неправильных предложения;
- помощь со словами;
- дополнительное аудио;
- **Duplicate**;
- **Delete**;
- **Move Up** и **Move Down**.

Карточки можно менять местами перетаскиванием. Внизу — **ADD STORY CARD**. Разрешено от 10 до 20 карточек. Картинка и правильное предложение обязательны. Номера событий — уникальные целые числа от 1 до количества карточек. После перестановки редактор предлагает автоматически перенумеровать карточки.

#### Шаг 3 — Preview

Учитель видит тему в том же игровом компоненте, что и ребёнок, но результат не сохраняется в профиль. Сверху остаётся заметная панель `Preview mode` с кнопкой возврата к редактированию. Нужно проверить обложку, весь текст, картинки, аудио и прохождение от начала до конца.

#### Шаг 4 — Save

Кнопки:

- **SAVE AS DRAFT** — сохраняет даже неполную тему, если базовая структура не повреждена;
- **SAVE AND PUBLISH** — запускает полную проверку всех ограничений и публикует только без ошибок;
- **BACK** — возвращает к Preview;
- **CANCEL** — выходит после подтверждения несохранённых изменений.

### 7.3. Ошибки простым русским языком

Ошибка показывается рядом с полем и в кратком списке сверху. Фокус переводится к первой ошибке. Примеры:

- «Введите название темы».
- «Добавьте Past Simple форму глагола».
- «Такая пара глаголов уже есть».
- «Для игры нужно минимум 4 пары».
- «Добавьте в предложение один пропуск ___».
- «Заполните все три варианта ответа».
- «Выберите правильный ответ».
- «Правильный ответ должен совпадать с A, B или C».
- «Для истории нужно минимум 10 карточек».
- «Загрузите изображение».
- «Номера событий не должны повторяться».
- «Файл слишком большой. Максимальный размер — 5 МБ».
- «Не удалось прочитать JSON. Проверьте файл».
- «В импортируемой теме отсутствуют обязательные поля».

### 7.4. Импорт, экспорт и удаление

Экспорт создаёт один JSON с метаданными и содержимым. В первой версии изображения и аудио внутри экспорта хранятся как Data URL только для небольших файлов; общий размер импортируемого JSON ограничивается 20 МБ. При превышении редактор просит уменьшить файлы. Импорт сначала проверяется и показывается в Preview, а сохраняется только после подтверждения. Неизвестные поля игнорируются, обязательные — проверяются.

Перед удалением показывается название темы и вопрос: «Удалить тему? Это действие нельзя отменить». Опубликованная тема, по которой уже есть результаты, удаляется из библиотеки, но старые результаты ученика сохраняются с названием темы.

## 8. Звуковая система

### 8.1. Набор звуков

Общие эффекты:

- нажатие кнопки;
- открытие карточки;
- правильный ответ;
- неправильный ответ;
- получение звезды;
- потеря сердца;
- открытие сундука;
- завершение уровня;
- экран победы;
- тихая фоновая музыка с египетским настроением.

Звуки короткие, спокойные, без резких пиков громкости, криков и пугающих эффектов. Ошибка должна звучать мягко, а не как наказание.

### 8.2. Настройки и запуск

В Settings находятся:

- `Sound Effects On/Off`;
- `Music On/Off`;
- громкость эффектов 0–100%;
- громкость музыки 0–100%.

Значения сохраняются. По умолчанию эффекты включены на 60%, музыка включена на 20%, но музыка не запускается до первого осознанного действия пользователя. Первым действием считается нажатие или касание внутри сайта. Изменение ползунка проигрывает короткий тест только по явному действию.

При скрытии вкладки музыка ставится на паузу. Одновременно играет не более одной фоновой дорожки. Кнопка Sound в шапке быстро выключает и возвращает оба канала, не забывая их прежнюю громкость.

## 9. Профили и прогресс учеников

### 9.1. Локальные профили

В первой версии нет интернет-аккаунтов. На одном устройстве можно создать несколько локальных профилей. Для каждого сохраняются:

- имя;
- аватар;
- текущий уровень;
- общее количество звёзд;
- пройденные игры;
- пройденные темы;
- лучший счёт по теме и игре;
- лучшее время;
- точность;
- число попыток;
- открытые достижения;
- дата последней игры.

Имя обязательно, 1–24 символа. Аватар выбирается из встроенного набора; пользовательскую фотографию в первой версии не загружаем, чтобы упростить приватность.

### 9.2. My Progress

По маршруту `/progress` показываются:

- имя и аватар;
- уровень;
- общая шкала до следующего уровня;
- общее число звёзд;
- отдельные результаты трёх игр;
- лучшие очки, время и точность;
- завершённые темы;
- достижения.

Если результатов нет, экран объясняет следующий шаг: `Play your first game to see your progress!`

### 9.3. Звёзды и уровни

- 1 звезда — игра завершена;
- 2 звезды — игра завершена с точностью не менее 70%;
- 3 звезды — игра завершена с точностью не менее 90%.

За одну тему в одном типе игры в общий баланс входит только лучший результат по звёздам. Повторное прохождение может улучшить результат, но не добавляет те же звёзды повторно. Каждые 10 накопленных звёзд повышают уровень: `level = floor(totalStars / 10) + 1`. Уровень 1 соответствует 0–9 звёздам.

## 12. Хранение данных и модели TypeScript

### 12.1. Что хранится в localStorage

`localStorage` подходит для небольших данных, которые нужны сразу:

- `egl.selectedStudentId` — выбранный ученик;
- `egl.students` — профили и сводный прогресс;
- `egl.gameResults` — компактные результаты без медиа;
- `egl.achievements` — открытые достижения;
- `egl.soundSettings` — настройки звука;
- `egl.teacherPin` — соль, хеш PIN и служебные данные блокировки;
- `egl.schemaVersion` — версия структуры данных.

Необходимо обрабатывать повреждённые данные: сохранить резервную копию строки, применить безопасные значения по умолчанию и не ломать страницу.

### 12.2. Что хранится в IndexedDB

База `english-game-library`, версия 1:

- `topics` — созданные темы и их метаданные;
- `images` — изображения как `Blob`;
- `audio` — аудиофайлы как `Blob`;
- `memoryPairs` — пары глаголов;
- `questQuestions` — вопросы;
- `storyCards` — карточки пользовательских историй.

Записи связываются через `topicId`. Удаление темы удаляет связанные медиа и содержимое одной транзакцией. Встроенные темы можно держать в `src/data`, а в IndexedDB хранить только созданные учителем материалы.

### 12.3. Короткие TypeScript-интерфейсы

```ts
type GameType = 'memory' | 'quest' | 'storyboard';
type TopicStatus = 'draft' | 'published';

interface StudentProfile {
  id: string;
  name: string;
  avatarId: string;
  level: number;
  totalStars: number;
  achievementIds: string[];
  lastPlayedAt?: string;
}

interface GameTopic {
  id: string;
  gameType: GameType;
  title: string;
  description: string;
  difficulty: 'easy' | 'medium' | 'hard';
  coverImageId?: string;
  maxStars: 1 | 2 | 3;
  status: TopicStatus;
}

interface MemoryTopic extends GameTopic {
  gameType: 'memory';
  pairs: Array<{ id: string; base: string; past: string; imageId?: string; audioId?: string }>;
}

interface QuestTopic extends GameTopic {
  gameType: 'quest';
  questions: Array<{
    id: string;
    sentence: string;
    verb: string;
    options: [string, string, string];
    correctIndex: 0 | 1 | 2;
    hint: string;
    explanation: string;
  }>;
}

interface StoryboardTopic extends GameTopic {
  gameType: 'storyboard';
  cards: Array<{
    id: string;
    eventNumber: number;
    title: string;
    imageId: string;
    correctSentence: string;
    wrongSentences: [string, string];
    wordHelp?: string;
    audioId?: string;
  }>;
}

interface GameResult {
  id: string;
  studentId: string;
  topicId: string;
  gameType: GameType;
  score: number;
  accuracy: number;
  elapsedSeconds: number;
  stars: 1 | 2 | 3;
  attempts: number;
  completedAt: string;
}

interface Achievement {
  id: string;
  title: string;
  description: string;
  unlockedAt?: string;
}

interface SoundSettings {
  effectsEnabled: boolean;
  musicEnabled: boolean;
  effectsVolume: number;
  musicVolume: number;
}
```

В рабочем проекте общие поля лучше вынести в отдельные типы, но здесь они намеренно показаны рядом для понятности.

### 12.5. Версии, резервирование и приватность

Все структуры получают версию схемы. При обновлении сайта выполняется миграция, а не молчаливое удаление. Teacher Editor должен предлагать экспорт тем; отдельный экспорт прогресса можно добавить позже. Очистка данных браузера удалит локальные профили, поэтому Settings предупреждает об этом. Никакие имена детей и результаты не отправляются наружу.

| `/teacher/topic/:topicId/edit` | Edit Topic | Редактирование темы. |

Неизвестный `topicId` показывает понятный экран `Topic not found` с кнопкой **HOME**. Черновик нельзя открыть через обычный игровой маршрут, кроме Preview внутри редактора. Неизвестный маршрут показывает страницу `Page not found`.

Перед уходом из незавершённой игры через **Home** показывается подтверждение. Пауза и модальные окна не требуют отдельных маршрутов.

## 15. Адаптивность

### 15.1. Большой экран

При ширине от 1100 px три карточки стоят в один ряд. Шапка показывает все кнопки. Карточки имеют одинаковую высоту, а основные действия выровнены снизу. Игровые панели располагаются вокруг центральной игровой области, не уменьшая её чрезмерно.

### 15.2. Планшет

При ширине 700–1099 px карточки можно показать как две в первом ряду и одну по центру во втором либо как горизонтальную прокрутку с видимой частью следующей карточки. Предпочтительный вариант — сетка 2 + 1, потому что все игры видны без скрытого жеста. Служебные кнопки становятся компактнее. В Memory число колонок подбирается так, чтобы карточки оставались читаемыми.

### 15.3. Телефон

До 699 px карточки идут в одну колонку. Брендовая иллюстрация уменьшается, часть декоративного пейзажа скрывается. Статистика игры переносится на две строки. Главные кнопки занимают почти всю ширину. Горизонтальная прокрутка всей страницы запрещена.

### 15.4. Размеры управления и текста

- минимальная активная область кнопки: 44 × 44 CSS px;
- рекомендуемая высота главной кнопки: 52–60 px;
- основной текст: не меньше 16 px на телефоне и 18 px в игровых заданиях;
- заголовки игровых карточек: примерно 24–32 px в зависимости от экрана;
- межстрочный интервал основного текста: не меньше 1.4;
- текст нельзя помещать внутрь растровой картинки.

### 15.5. Карточки и сенсорное управление Storyboard

Карточки сохраняют пропорции, изображение обрезается только через предсказуемый контейнер, полный смысл доступен через `alt` и подпись. На телефоне линия времени Storyboard делится на вертикальные или горизонтально прокручиваемые группы по 2–3 позиции. Во время перетаскивания страница не должна случайно прокручиваться в направлении жеста. Обязательно есть альтернатива: выбрать карточку, нажать **MOVE**, затем выбрать номер позиции. После перемещения озвучивается текстовое подтверждение для вспомогательных технологий.

## 16. Доступность и удобство

- Контраст текста и управления соответствует минимум WCAG AA: 4.5:1 для обычного текста, 3:1 для крупного текста и границ управления.
- Основной текст крупный и не зависит от декоративного шрифта. Декоративный шрифт используется только в коротких заголовках.
- Все кнопки имеют видимые подписи; иконка без текста получает доступное имя.
- Значимые изображения имеют точный `alt`; декоративные скрыты от скринридера.
- Вся навигация, Memory и Storyboard доступны с клавиатуры.
- Фокус хорошо заметен золотой или светлой обводкой достаточного контраста.
- Звук можно отключить в любой момент.
- Информация не передаётся только цветом: используются текст, значки и форма рамки.
- После ошибки показывается понятное объяснение и следующий возможный шаг.
- Не используются пугающие звуки, изображения или резкие вспышки.
- Анимации учитывают `prefers-reduced-motion`.
- Таймер не прерывает игру: он нужен для бонуса, а не как жёсткое ограничение.
- Модальные окна удерживают фокус, имеют заголовок и возвращают фокус на кнопку открытия.
- Текст интерфейса допускает увеличение браузером до 200% без потери функций.

## 20. Важные ограничения реализации

- Первая версия не использует сервер, онлайн-регистрацию и облачную синхронизацию.
- Нельзя встраивать весь референс как фон страницы.
- Нельзя делать текст частью изображений, если он нужен для управления или обучения.
- Пользовательские медиа хранятся локально и могут исчезнуть после очистки данных браузера.
- Teacher PIN не заменяет настоящую авторизацию и не защищает данные от технически подготовленного пользователя устройства.
- Публикация темы возможна только после полной проверки, Draft может быть незавершённым.
- Таймер не завершает игру принудительно; он влияет только на бонус.
- Все формулы очков, точности, звёзд и уровня едины для повторных прохождений.
- В ходе подготовки этого документа не должны создаваться компоненты, CSS, библиотеки, заглушки или изменения существующего кода. Единственный результат текущего задания — этот файл `GAME_SPEC.md`.

## 21. ASSUMPTIONS

1. Файл `main- interface.png.png` в корне считается фактическим визуальным референсом вместо отсутствующего `public/images/main-interface.png`. При начале разработки путь будет уточнён или ресурс будет аккуратно перемещён.
2. Интерфейс ученика и игровые инструкции — на простом английском; Teacher Editor, проверки и технические пояснения учителю — на русском.
3. У каждой встроенной игры первой версии есть минимум одна опубликованная тема Past Simple.
4. Игровой таймер считает время вверх и не останавливает игру; «до окончания времени» в короткой инструкции означает завершить как можно быстрее ради бонуса.
5. Единый бонус времени для Mummy Memory и Verb Treasure Quest равен `max(0, 300 − elapsedSeconds)`, максимум 300.
6. В Quest три сердца обновляются для каждого вопроса; ребёнок всегда может завершить всю учебную сессию.
7. В Storyboard встроенная история содержит 10 карточек, пользовательская — 10–20, поэтому номера линии времени создаются динамически.
8. В Storyboard доступно три подсказки, одна подсказка открывает одну позицию и стоит 5 очков.
9. Заработанные за тему звёзды не суммируются при каждом повторе: в общий баланс входит лучший результат. Иначе уровень можно было бы бесконечно повышать одной и той же темой.
10. Значение `maxStars` в теме задаёт верхнюю границу награды, но стандартные темы используют 3, чтобы сохранить систему порогов.
11. Удаление опубликованной темы не удаляет исторический результат ученика.
12. В первой версии аватары выбираются из безопасного встроенного набора; фотографии детей не загружаются.
13. Допустимые форматы изображений — JPG, PNG, WebP до 5 МБ; аудио — MP3, OGG или WAV до 10 МБ; общий импорт JSON — до 20 МБ.
14. Значения громкости в интерфейсе показываются как 0–100%, а в данных сохраняются числа от 0 до 1.
15. Визуальные персонажи и обложки должны быть оригинальными или иметь подтверждённые права использования.
